# Pharmacy Database Management System

## Overview

This project developed a relational database management system for a local pharmacy in Midtown Manhattan. The system was designed to replace spreadsheet-based and verbal methods of tracking pharmacy information with a centralized database.

Disclaimer: This project is for academic purposes. The pharmacy, patients, prescribers, medications, insurance information, and all other data represented in the database are entirely fictional and do not contain real patient or business information.

The database organizes information related to patients, prescribers, medications, prescriptions, insurance plans, pharmacies, filled prescriptions, inventory, drug codes, and postal codes.

## Project Objectives

- Organize pharmacy information into related database tables
- Maintain patient, prescriber, medication, and prescription records
- Track filled prescriptions and insurance information
- Manage pharmacy medication inventory
- Establish relationships between database entities using primary and foreign keys
- Use SQL to create tables, define relationships, insert data, and retrieve information
- Create Microsoft Access forms, queries, reports, and a navigation interface

## Database Entities

The database includes the following major entities:

- Patient
- Prescriber
- Medication
- Prescription
- Insurance Plan
- Pharmacy
- Filled Prescription
- Inventory
- Drug Codes
- Postal Codes

## SQL

The `sql` folder contains SQL documented in the project report, including:

The project was implemented using Microsoft Access and included:

- Data-entry forms
- Subforms
- Queries
- Reports
- Navigation form

These components were used to support data entry, information retrieval, and pharmacy management.
